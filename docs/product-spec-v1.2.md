# Portal Fitness 产品方案 v1.2

> 日期：2026-09-15  
> 状态：MVP 单一产品真源  
> 合并范围：原 Figma Make 星球原型 + 当前仓库训练记录、训练方案、动作库与 Credit 系统

## 1. 产品定义

**你的身体是一颗星球。**

Portal Fitness 是一款手机端游戏化健身 App。基础训练工具负责让用户可靠地记录真实运动；Credit 与星球系统把训练结果转化为可见、可积累、可回顾的成长。

MVP 不把星球作为装饰，也不把视频识别作为训练门槛：

- 完成有效训练即可获得基础 Credit。
- 每日签到提供少量基础额度，保证低门槛反馈。
- 用户可选录制一个训练动作；AI 核验通过后获得额外 Credit。
- 永久地形不随每次训练即时修改，而是在时间与 Credit 同时达标后生成。

## 2. MVP 范围

| 模块 | MVP 必须具备 | 暂不进入 MVP |
| --- | --- | --- |
| 账户与新手 | 登录/注册、基础资料、目标与限制、星球命名与初始创建 | 社交关系、家庭账户 |
| 星球养成 | 星球首页、每日额度、Credit 进度、周期进化、版本历史 | 无限自由生成、付费直接升级 |
| 训练底盘 | 快速开始、动作库、力量/距离/游泳/时长记录、方案、历史 | 大规模课程视频生产 |
| 视频加成 | 可选录制/上传、动作与画面可用性判断、结果解释、重录/跳过 | 医疗诊断、康复处方、专业裁判评分 |
| 数据与我的 | 周训练摘要、Credit 明细、隐私设置、数据删除/导出入口 | 复杂健康报告解读 |

## 3. 手机端信息架构

底部导航固定为 4 个 Tab：

| Tab | 主要职责 | 二级页面 |
| --- | --- | --- |
| 星球 | 今日反馈、每日额度、进化进度、守护者叙事 | 3D 全览、进化仪式、星球版本 |
| 训练 | 快速开始、今日方案、继续未完成训练 | 动作库、训练记录、视频核验、结算 |
| 方案 | 方案列表、AI 生成入口、方案编辑 | 目标与条件、动作编排 |
| 我的 | 身份、周摘要、训练历史、Credit 明细 | 体成分、隐私、通知、数据管理 |

动作库是训练流程中的二级页，不占用底部导航；训练历史并入“我的”，避免工具能力挤压星球主线。

## 4. 核心用户闭环

### 4.1 新手首日

登录/注册 → 基础资料 → 目标与限制 → 命名并创建星球 → 领取首日额度 → 完成第一次训练 → 可选视频加成 → Credit 结算 → 首次星球进化。

非必要资料均允许跳过。目标是在 3 分钟内让用户进入第一次训练。

### 4.2 日常训练

星球首页 → 今日训练/快速开始 → 选择动作或方案 → 记录组次/距离/时长 → 完成训练 → 基础 Credit 到账 → 可选视频核验 → 结算 → 返回星球查看即时反馈。

### 4.3 周期进化

日常训练只产生星核发光、能量注入、地貌虚影等即时反馈。永久地貌变化必须同时满足最短时间和 Credit 门槛：

| 进化次数 | 最短间隔 | 建议 Credit 门槛 | 设计目的 |
| --- | ---: | ---: | --- |
| 首次 | 当天 | 60 | 尽快让新人看到养成结果 |
| 第二次 | 3 天 | 160 | 建立连续行为 |
| 第三次 | 5 天 | 240 | 拉长期待周期 |
| 稳定期 | 7 天 | 320 | 建立稳定周循环 |

时间已到但 Credit 不足时继续积累；Credit 已够但时间未到时展示倒计时。生成失败不扣 Credit，用户可以稍后重试。

## 5. Credit 系统

以下为 MVP 默认配置，正式上线后由服务端规则版本控制：

| 来源 | 默认奖励 | 规则 |
| --- | ---: | --- |
| 每日签到 | +5 | 每自然日一次，不改变永久地形 |
| 有效训练 | 最低 +20 | 按已完成组数、距离、时长与运动类型计算；单次封顶 120 |
| 视频通过 | +15 | 可选；仅在画面可用且目标动作达到基础标准时发放 |
| 每日封顶 | 200 | 防止刷分和报复性训练 |

视频低置信度、识别失败或用户跳过时，基础训练 Credit 必须保留。

## 6. 训练底盘

### 6.1 动作库

以 `src/exerciseLibrary.ts` 为唯一数据源，当前覆盖 265 个动作及运动项目：力量、跑步、有氧器械、游泳、户外、拉伸恢复、瑜伽身心与球类综合。

每个动作必须包含稳定 ID、分类、肌群/训练部位、器械、别名和记录模型。历史记录与训练方案只能保存动作 ID。

### 6.2 记录模型

| 类型 | 字段 |
| --- | --- |
| 力量 | 组、重量、次数、RPE、完成状态 |
| 距离 | 距离、时长、平均配速 |
| 游泳 | 距离、趟数、泳姿、时长 |
| 时长 | 时长、课程/动作备注 |

未完成训练保留为草稿；完成后生成不可变结算快照，后续修改通过补充记录而不是静默改写历史 Credit。

### 6.3 训练方案

用户可以新建、编辑、复制、删除并直接开始方案。AI 生成计划也必须写入同一套可编辑的数据结构，并经过频次、总量、限制条件和动作可用性的安全校验。

## 7. AI 视频核验

### 7.1 MVP 判断范围

1. 画面中是否有可用的完整人体骨架。
2. 是否为用户选择的目标动作。
3. 是否完成最低次数或完整动作周期。
4. 基础幅度、稳定性和节奏是否达到奖励标准。

不判断医学风险，不诊断伤病，不使用“正确/错误姿势”作为医疗结论。

### 7.2 推荐技术链路

录制 8–15 秒视频 → 端侧 MediaPipe/MoveNet 提取关键点 → 上传骨架时序与必要的低清片段 → 服务端动作分类与规则评分 → 置信度门槛 → 通过/低置信度/不可用三态结果。

- 通过：发放视频加成并展示 2–3 条可解释结果。
- 低置信度：允许重录或跳过，基础 Credit 保留。
- 不可用：说明遮挡、距离或光线问题，不对动作质量下结论。
- 原视频默认 72 小时自动删除；是否保存用于历史回看必须单独授权。

## 8. AI 星球进化

MVP 采用“确定性模型 + AI 生成资产”的混合方案：

1. 聚合一个进化周期内的力量、有氧、恢复、签到和体成分贡献。
2. 规则层确定主要地貌类型、幅度上限和禁止区域。
3. AI 在现有星球版本基础上生成高度图、纹理或受控地形资产。
4. 客户端在预制网格上应用新资产并生成预览。
5. 用户确认后写入新的 `planet_version`。

每个版本保存父版本、生成种子、模型版本、输入贡献快照、参数、资产 URL 与时间，保证结果可复现、可审计。视频原件不进入星球生成输入。

## 9. 数据与合规

- 行为数据、体成分数据、视频数据分层存储。
- 健康与身体数据单独授权，支持撤回、删除和导出。
- AI 输出不得提供诊断、治疗或用药建议。
- 训练受伤/疼痛信息只用于过滤动作和训练量，不用于自动推断疾病。
- 减少动态效果跟随系统设置；星球待机动效在低电量或后台停止。

## 10. 指标与验收

| 层级 | 指标 |
| --- | --- |
| 北极星 | 周活跃训练用户数（WAU-T） |
| 新手漏斗 | 注册完成率、首次训练完成率、首次进化到达率 |
| 核心闭环 | 训练完成 → 返回星球转化率、星球周访问频次 |
| 视频价值 | 视频选择率、可用视频率、通过率、低置信度率、重录率 |
| 留存 | D1、D7、W4 |

MVP 验收必须覆盖登录、星球、训练记录、Credit、可选视频加成和周期进化六条主链路，并有空态、加载、失败、重试与隐私说明。
