## 1. 风格基准

“都市美漫 + 轻度写实”用于人物；“克制的自然游戏地貌”用于星球；两者用深色背景、自然光、鼠尾草绿与青蓝数据色统一。整体应有健身运动的效率和成熟训练搭档的亲近感。

核心视觉顺序：操作与数据清晰 → 人物身份稳定 → 地貌有层次 → 少量潮流细节。每个页面只安排一个主要视觉焦点，人物、星球与大数字不同时争抢首屏。

认可的 [界面与人物参考](../visual-directions/2026-10-05/README.md) 和 [交互图](../visual-interactions/2026-10-06/README.md) 为画法、服装与页面构图参照。图片中的字应重新排版，独立资产应重新生产。

## 2. 人物与陪伴

| 项目 | 生产要求 |
| --- | --- |
| 比例 | 成年人自然头身比例、真实关节和肩胯结构；面部仅轻微简化 |
| 画法 | 明确但细致的轮廓，简化明暗块与柔和体积光兼用；脸与手比服饰更精细 |
| 面部 | 正常眼睛尺度、自然鼻梁/嘴唇/下颌，轻微不对称；友好专注，避免夸张戏谑 |
| 体态 | 健康运动气质，功能性动作；力量感通过站姿与肩背表达，避免极端肌肉夸张 |
| 服饰 | 炭黑功能运动服、轻型技术背心或外套、训练鞋、智能腕表；少量 sage/teal 缝线或配件 |
| 技术感 | 来自运动面料、简洁装备与精确界面；角色本体不铺满发光线路或战甲 |
| 多背景 | 三位搭档保留各自面部、肤色、发型特征，使用同一绘制质量；不以背景定义性格或能力 |
| 连续性 | 同一角色的脸型、发型、身材、服装与配件跨页一致；按参考建立正面/侧面/背面与表情表 |
| 扩展 | 当前三张是女性角色参考，不能视为已经覆盖全部受众；后续男性角色沿用同一画法，另行评审 |

角色工作名：Maya（白人参考）、Jordan（黑人参考）、Kai（东亚参考）。产品不显示族群标签作为能力分类；选择卡使用名称、形象与一行中性的陪伴介绍。

初次资产切片只需：一个首页邀请姿态、一张训练陪伴半身、一张完成反馈、一个圆形头像、对应身体透视层。建议表情为平静、鼓励、专注、轻微庆祝；避免高频跳跃、卖萌和大面积表情贴纸。

英文语气短、积极、有行动目标：`Ready when you are.` / `One session, one step forward.` / `Look closer at your world.` 不使用羞辱、强迫打卡或身体优劣评价。

## 3. 半身透视与身体分析

人物完整轮廓和正常表情保持不变，以纵向分界呈现一侧外观、一侧半透明骨骼/肌肉。骨架与肌肉对齐正常解剖结构，使用低饱和青白与暗红褐，透视区控制亮度以保留轮廓。允许少量连线对应四项指标，连线不可穿过面部或主要数字。

优先制作“外观、骨骼、肌肉、分界蒙版”独立图层，让程序控制透视强度。小头像不显示解剖细节。透视插画是身体分析的艺术表达，页面称 `Body overview`，不称实时扫描或设备检测；综合评分与趋势在没有数据规则时标注 demo 或不显示。

## 4. 目标界面令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `surface-base` | `#101419` | 页面基础底色 |
| `surface-card` | `#1B2228` | 普通信息卡 |
| `surface-raised` | `#26313A` | 弹层、输入、选中面板 |
| `text-primary` | `#F4F6F3` | 主文字与关键数字 |
| `text-secondary` | `#B8C2C5` | 辅助文字与单位 |
| `action-primary` | `#C2D995` | 主按钮、进度、明确选中态 |
| `action-on-primary` | `#101419` | 主按钮文字与图标 |
| `data-accent` | `#7AAEB4` | 水分、曲线、数据细节 |
| `feedback-warning` | `#E3BA78` | 需要注意、待确认 |
| `feedback-error` | `#F08E88` | 字段错误、加载失败 |
| `border-subtle` | `#39464F` | 卡片分隔，不能单独承担选中识别 |

鼠尾草绿只用于动作、进度和选中，不铺满背景。青蓝用于数据与水体；自然土黄、森林绿和冰白主要留给地貌。主按钮为实色，卡片为稳定暗面，薄玻璃感只在地图控件少量使用。

正文采用系统无衬线栈 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`；数字使用等宽数字特性 `font-variant-numeric: tabular-nums`。标题通过字重和尺寸体现运动感，不使用全页漫画装饰字体。现有 Bangers / Comic Neue / ZCOOL KuaiLe 仍属于运行版本，替换需接入并核验布局。

| 元素 | 移动端目标规格 |
| --- | --- |
| 页面标题 | 28–32px / 700–800，行高 1.15–1.25 |
| 区块标题 | 18–20px / 600–700 |
| 主指标 | 28–40px / 700，单位 12–14px |
| 正文 | 15–16px，行高 1.4–1.5 |
| 次级说明 | 12–14px，行高至少 1.4；底栏标签至少 11px |
| 间距 | 4px 基础阶梯；页面边距 20px，窄屏可降到 16px；区块间 24px |
| 圆角 | 卡片 18px，输入 12px，主按钮 14px；药丸形仅用于小标签 |
| 图标 | Lucide 统一线条，常规 20–24px；附文字或可访问名称 |
| 主按钮 | 高 48–52px；每个视图一个主要动作 |
| 触控 | 有效区域至少 44×44px，画布控件与关闭按钮同样适用 |
| 底栏 | 五项文字+图标，64px 内容区加安全区；页面下留足滚动空间 |

正文与底色的对比目标 ≥4.5:1，关键图标与状态轮廓 ≥3:1。状态同时有文字、图标或轮廓变化。禁用态清晰但不得用不可读灰字表达失败原因。输入错误就近显示，保存期间防重复点击。

本轮静态计算：主文字/卡片 14.80:1，辅助文字/卡片 8.85:1，主按钮文字/底色 12.02:1，青蓝数据色/卡片 6.54:1。实际图片背景、透明面板和字号仍需在页面接入后检查。

## 5. 通用组件与状态

| 组件 | 状态与规则 |
| --- | --- |
| 阶段卡 | 五阶段浏览、当前位置、阶段名称；图片区与文字区分层，右侧小球只读 |
| 训练卡 | 模式、预设时长/热量、搭档；选中后显式 Start，禁止以视觉模拟真实计时 |
| 任务行 | 未完成/展开/完成/撤销；已完成附 check 与奖励说明 |
| 周进度 | 完成数/目标，展示封顶；多余训练另列，不溢出进度条 |
| 指标卡 | 指标名、数值、单位、对应地貌；没有数据用 `—` 和补充入口 |
| 区域详情 | 地貌、对应身体值、Focus/Back；文字在地图之外可读 |
| 表单 | 默认、编辑、错误、保存中、成功、失败；取消回滚草稿 |
| 反馈 | 可见的成功/失败信息；不只依赖短暂消失的颜色闪烁 |
| 搭档卡 | 默认/选中/保存中/失败；选中描边+勾选，页面头像同步 |

加载时使用轮廓和真实 loading 文案，不预填伪造指标。底栏高亮与页面一致；弹层关闭后焦点回到触发入口；地图外部提供旋转/缩放/复位替代控件。页面范围见 [PAGE_CONTENT](PAGE_CONTENT.md)。

## 6. 动效与响应式

按钮反馈 120–180ms，卡片/面板切换 180–260ms，地图相机聚焦 600–900ms 为目标区间。成功反馈用一次轻微亮度/进度变化，避免持续粒子喷发。星球慢速自转可关闭；详情出现时停止自转；减少动态效果偏好下取消大幅移动与持续自转。

以 390px 宽作为设计基准，检查 320px、430px 与桌面窄栏。小屏采用单列、指标两列；地图区域不因长文案挤成小缩略图，详情可用底部面板。横屏或宽屏保持移动应用清晰的信息层级，不直接拉伸为满屏大卡。英文长字符串、单位、键盘弹出与底部安全区必须单独检查。

## 7. 生产、文件与验收

概念 PNG 留在 `docs/`，当前运行 WebP/GLB 留在 `public/assets/`，两类资源分别标注。正式人物优先交付分层源稿及透明 PNG，再导出保留 alpha 的 WebP；正式地貌卡背景不得烘焙文字、按钮或星球。命名使用语义和版本，如 `partner-maya-home-v1.webp`；更新 [assets.md](../assets.md) 才能宣称入库/接入。

先做一个搭档和一组核心页面，完成视觉检查后再复制到另外两位搭档。3D 人物、绑定、动画、Blender/Godot 交接不在本轮交付内；若后续使用，需另行定义工程、骨架、动作与验证，不把概念 PNG 当作模型输入已完成。

视觉完成条件：选定角色跨页脸型服装一致；成人比例与半身透视对齐；暗色文字清晰；每页主操作明确；无乱码或烘焙文字；没有过度萌化、怪诞和霓虹；五阶段与星球同一世界；正常/加载/错误/空数据状态齐全；实际浏览器截图和资产索引可核对。构建成功仅是工程检查，不替代视觉验收。
