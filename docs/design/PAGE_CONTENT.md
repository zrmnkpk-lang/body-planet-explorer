## 1. 产品范围与数据

核心体验：知道今天做什么 → 和搭档完成训练 → 看到自己的星球 → 记录身体数据 → 持续回来。导航保持 Home / Train / Planet / Body / Me 五页；本次不扩展登录、社交、商店、抽卡、订阅或设备配对流程。

现状行为以 [interaction-spec.md](../interaction-spec.md) 为准，逐项视觉触发编号以 [交互图册](../visual-interactions/2026-10-06/README.md) 为准。本文件定义目标页面内容与新增状态；“建议”表示需要 GLM 开发，不能直接对外宣布已有。

设计演示使用用户 Alex、搭档 Maya、LV.5、320/800 XP、周进度 3/5，肌肉 32.8kg、水分 58.3%、骨量 3.1kg、体脂 18.7%；都是同一套假数据，未改变运行默认值。角色工作名与英文 copy 可在落地时统一校对。

目标数据只建立一份来源：`bodyMetrics`、`workoutSession`、`workoutHistory`、`dailyTasks`、`weeklyProgress`、`xp/level`、`selectedPartner`、`reminderPreference`。首页与 Me 读取同一个等级/XP；Body 与 Planet 读取同一份已保存指标。具体 store 技术由 GLM 选择，本文件不要求引入新框架。

## 2. Home：四个核心区域

最新基准为 [首页 v2](../visual-interactions/2026-10-07/01-home-plan-history-body-v2.png)，详细流程与验收见 [最新首页交接](../visual-interactions/2026-10-07/README.md)。上一版首页保留为历史参考，其他四页继续沿用 2026-10-06 图册。

| 顺序 / 模块 | 内容 | 操作与结果 |
| --- | --- | --- |
| 1 My Planet | 等级、阶段、XP 和只读小球 | 卡片入口进入 Planet；不在首页操作小球 |
| 2 Today's plan | 任务数、完成数、搭档半身、View plan | 展开今日计划面板，不启动训练 |
| 3 History | This week · 3/5、七日完成标记、View history | 进入训练历史；详情页面另设计，完成数与真实记录同源 |
| 4 Body overview | 肌肉、水分、骨量、体脂四指标、View details | 进入 Body；缺失值显示 — |

顶部保留问候，底栏保持五页。成长信息合并至星球卡，旧版独立每日任务列表与训练菜单由今日计划替代。人物与暗黑黄绿色视觉沿用都市美漫、轻度写实方向。

Today's plan 面板显示 1/3 completed 和 Edit。力量训练可展开，图示 20 分钟由热身 3 分钟、主训练 14 分钟、放松 3 分钟组成，显式 Start training 才进入对应会话；Walking 显示 8,000 steps，Hydration 显示 2,000 ml 与 Completed / Manually recorded。

Edit 建立独立草稿，调整当天训练总时长、步数目标、饮水目标。Cancel 或关闭丢弃草稿并返回计划；Save changes 保存后返回计划并更新首页。仅影响当天，不改长期模板与历史；保留已完成记录，不能重复奖励。步长、上下限、总时长分配与目标调整后的完成判定须在实施前明确；20 分钟示例不覆盖 Train 三模式既有预设。

状态包含首页正常/无记录/载入、计划展开/折叠/完成、编辑草稿/保存/失败重试。功能由 GLM 实施；本次只更新设计说明，不代表运行界面已替换。

## 3. Train：选择 → 训练 → 结算

对应 [图02](../visual-interactions/2026-10-06/02-training-session-summary-v1.png)。当前三模式与目标文案：

| 模式 | 英文工作名 | 现有预设 | 地貌事件预告 |
| --- | --- | --- | --- |
| 造山力量 | Mountain Strength | 45min / 310kcal | Mountain movement |
| 季风有氧 | Monsoon Cardio | 30min / 420kcal | Passing monsoon |
| 晨雾恢复 | Morning Recovery | 20min / 160kcal | Morning mist |

热量必须标为预设/估算，不能作为设备测量；图中 `12:48` 与组数是流程示意，现状计时固定。没有心率数据源，不新增心率读数或实时传感器图。

| 状态 | 内容与动作 | 目标规则 |
| --- | --- | --- |
| 选择 | `Choose your session`，三模式，明确选中态，`Start session` | 选择不计时，开始才建立一次 session；同一时刻一个进行中会话 |
| 进行中 | 模式、真实计时、已定义训练进度、搭档短句；`Pause` / `Finish session` | 不用固定演示值冒充真实进度；动作组数需有实际计划才显示 |
| 暂停（建议） | `Session paused`；`Resume` / `End session` | 暂停停止计时，恢复沿用原会话 |
| 结束确认（建议） | `End this session?`；`Keep training` / `End without reward` | 提前终止与完成分开；返回路径清楚，不误发完成奖励 |
| 结算 | `Session complete`、实际时长、奖励摘要、生态事件预告 | 完成入账只一次；+46 XP 是现有预览，正式规则待定 |
| 下一步 | `Explore planet` / `Back to workouts` | 进入 Planet 或回选择；展示真实状态，不伪造地形改变 |

G-02 必须先确定训练 XP 与每日任务 +120 XP 的关系，避免同次训练不透明地重复累加。记录、奖励、任务完成与周次数要能追溯到同一个 sessionId。刷新恢复、跨页返回与取消行为纳入 GLM 验收；结算失败保留训练记录并可重试。

## 4. Planet：观察完整世界与区域

对应 [图03](../visual-interactions/2026-10-06/03-planet-explore-region-states-v1.png)，美术依据 [星球规范](PLANET_ART.md)。标题 `My Planet`，说明建议 `A world inspired by your body data.`，避免把艺术映射写成医学分析。

首屏给地图足够面积；下方或底部面板显示四项指标，地图内只放少量区域名。区域工作名 Mountain Belt / Deep Ocean / Polar Ice / Monsoon Lands 对应现有四个语义区。骨量仍映射极地，体脂对应气候，不把四项直接当作海陆面积。

| 状态 / 操作 | 页面反馈 | 现状差距 |
| --- | --- | --- |
| 进入 | 模糊轮廓、`Loading your planet…`、指标占位 | 需 renderer 首帧 ready 协议，不仅 iframe onLoad |
| 就绪 | 完整球体、控件、四项已保存值、搭档一行提示 | 复用统一 renderer，避免首页与生态版本分叉 |
| 探索 | 单指拖动/鼠标拖动旋转，双指/滚轮/+− 缩放，自转开关、Reset | 当前触屏短按可能被拖拽处理吞掉，G-04 修复 |
| 选区 | 停止自转，细轮廓、区域名和指标详情 | 点击与拖动必须区分，背面标签隐藏 |
| 聚焦 | `Focus region` 拉近同一区域 | 保持地理连续，近距离查看而非地面行走 |
| 退出详情 | `Back to globe` 或关闭，返回全貌 | 恢复约定相机，不随机换种子 |
| 无指标 | `Add your body data`，四卡显示 `—` | 可看默认演示星球，不能填伪造身体值 |
| 失败（建议） | `Planet unavailable`，`Try again` | 保留底栏，重试可恢复；加载超时、模型失败要可识别 |

Body 保存后先更新四指标及详情值。当前不重建几何；若 G-05 未开发，反馈只写 `Body data updated`。数据地图、标签和控件必须可读，配色不承担唯一选中识别。

## 5. Body：透视示意与可靠录入

对应 [图04](../visual-interactions/2026-10-06/04-body-analysis-entry-validation-v1.png)。标题 `Body overview`，人物半身透视为主图，四项数值靠近但不遮挡身体轮廓。角色随已选择搭档保持画法一致，透视图不是相机扫描结果。

| 模块 | 内容 | 目标行为 |
| --- | --- | --- |
| 指标概览 | Muscle kg / Water % / Bone kg / Body fat %，记录时间/来源 | 无来源时写手动录入，缺失显示 `—` |
| 主入口 | `Update body data` | 开启独立草稿，初始化为最近保存值 |
| 表单 | 四字段、固定单位、小数输入 | 百分比为有限值 0–100；kg 为有限正数；业务上限另定 |
| 编辑 | `Cancel` / `Save changes` | 输入只改草稿；取消返回已保存值，Planet 不被草稿污染 |
| 校验 | 就近错误说明，如 `Enter a value between 0 and 100.` | 空值、非数字、负数、NaN/Infinity 不进入已保存状态 |
| 保存 | 禁用重复提交，成功 `Body data updated` | 同时更新 Body 与 Planet；不写已重建地形 |
| 失败 | 保留草稿和原值，`Couldn't save your data. Try again.` | 允许重试，取消不会删除原记录 |
| 趋势 | 日期、数据项与最近记录 | 当前十二月趋势/综合评分为演示；无真实历史不绘制伪造走势 |

首个功能切片可用本地持久化完成真实保存，明确存储范围与刷新恢复；账户/云同步另行立项。单位、值和记录时间应独立保存，避免将格式化字符串用作数值。不得由示意人体尺寸推断真实身体比例。

## 7. 跨页状态与信息规则

1. Home 的 View plan 只展开当日计划；计划面板的 Start training 或 Train 的 Start 才启动对应训练。进行中切页后保留同一会话，不能切回时重新奖励或重置。
2. 完成结算有唯一记录，更新 XP、周进度和任务；撤销手动任务与训练记录的关系由 G-02 明确，不静默删除真实训练。
3. Body 输入草稿不触发 Planet；成功保存才发布新的已保存数据；失败或取消保留旧世界与旧值。
4. 同一搭档、同一用户身份、同一 XP/等级跨页一致；风格与装备不因小头像而换成萌化版本。
5. 刷新后的恢复取决于已实现的存储能力。未接入存储时仍如实描述会话状态，不能只用成功 toast 假装持久化。
6. 返回保留合理滚动/焦点；底栏有可读标签、安全区和明确高亮。非交互图片不拦截手势，弹层状态与路由协调。
