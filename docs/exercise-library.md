# 训练动作库与记录契约

动作库的唯一数据源是 `src/exerciseLibrary.ts`。动作选择、方案创建和训练记录必须引用稳定的 `exercise.id`，不能只保存展示名称。

## 覆盖范围

| 分类 | 示例 | 记录模型 |
| --- | --- | --- |
| 力量 | 杠铃、哑铃、器械、自重、壶铃、弹力带、举重 | 组数、重量、次数、RPE、完成状态 |
| 跑步 | 路跑、跑步机、轻松跑、节奏跑、间歇跑、越野跑 | 距离、时长、平均配速 |
| 有氧 | 骑行、室内单车、椭圆机、划船机、登山机、跳绳 | 距离、时长；无距离时允许只记时长 |
| 游泳 | 四种泳姿、混合泳、开放水域与专项练习 | 距离、趟数、泳姿、时长 |
| 户外 | 步行、徒步、登山、攀岩、滑雪、皮划艇、桨板 | 距离、时长；按项目允许距离为零 |
| 拉伸恢复 | 关节灵活性、局部拉伸、泡沫轴、热身和冷身 | 时长、备注 |
| 身心 | 瑜伽、普拉提、太极、八段锦、冥想和舞蹈 | 时长、备注 |
| 球类综合 | 足篮排、羽网乒、格斗、冰雪与其他竞技项目 | 时长、备注 |

当前库通过分组构造器维护，包含中文名称、常见英文/中文别名、分类、训练部位、器械和记录模型。前端搜索同时匹配这些字段。

## 扩展规则

1. 在对应分组的 `names` 尾部追加动作，避免改变已有索引型 ID。
2. 新动作必须明确 `tracking`，只能是 `sets`、`distance`、`duration` 或 `swim`。
3. 同义名称写在 `|` 后并用 `/` 分隔，例如 `杠铃深蹲|背杠深蹲/Back Squat`。
4. 不同记录模型的动作不要共用 ID；展示名称可以相近，但数据口径必须明确。
5. 删除已发布动作前应先迁移历史记录，避免已有 `exerciseId` 无法解析。

## MVP 持久化

浏览器本地使用以下键：

| 键 | 内容 |
| --- | --- |
| `portal-workout-sessions-v1` | 已完成训练记录 |
| `portal-active-session-v1` | 尚未保存的训练 |
| `portal-workout-plans-v1` | 用户训练方案 |
| `portal-exercise-favorites-v1` | 收藏动作 ID |

正式账号系统上线后，应把这些结构迁移到服务端，并保留离线草稿与同步冲突处理。

## Credit 结算

- 力量训练按已完成组数计算，未勾选完成的组不计入。
- 距离运动综合时长与距离计算；游泳采用独立权重。
- 时长类活动按有效时长计算。
- 单次训练最低 20、最高 120 Credit，避免极短记录无反馈或异常数据冲击周进度。
- 当前稳定周目标为 320 Credit；后续应由服务端规则版本控制，前端只展示结算结果。
