# Figma Make 参考项目与当前仓库差异

> 对比日期：2026-09-15  
> 参考输入：用户提供的“健身App网页.zip”  
> 目标：保留两边已完成能力，统一到 [MVP 产品方案](product-spec.md) 与 [手机端交互逻辑](interaction-spec.md)。本文记录目标与代码现状的差异，不把规划能力描述为已实现。

## 1. 结论

两套实现不是简单的新旧版本关系，而是互补分支：

- 参考项目完整呈现了星球首页、训练模式、3D 生态、体成分和个人页，但训练记录仅为演示状态。
- 当前仓库实现了可用的训练记录、方案、265 个动作库、本地持久化和 Credit 结算，但星球、账户、每日额度、视频加成与体成分主流程尚未并入 React 主界面。

因此不能用参考项目覆盖仓库；正确方案是以当前训练底盘为基础，恢复星球主线并补齐手机端流程。

## 2. 功能差异矩阵

| 能力 | 参考项目 | 当前仓库 | 当前处理 |
| --- | --- | --- | --- |
| 手机壳式星球首页 | 已有演示 | 缺失 | 作为登录后默认 Tab 恢复 |
| 3D 星球探索 | `PlanetView.tsx` + `ThreeBodyPlanet.tsx` | 独立 `src/app.js` 原型 | 后续并入 React 星球全览页 |
| 体成分录入 | 已有演示 | 缺失 | 并入“我的”二级页 |
| 个人设置 | 已有基础演示 | 缺失 | 补隐私、通知、导出与删除入口 |
| 动作库 | 无真实库 | 265 个动作 | 保留当前仓库实现 |
| 结构化训练记录 | 仅模式切换 | 已实现四种记录模型 | 保留当前仓库实现 |
| 训练方案 | 无编辑能力 | 已实现增删改和开始训练 | 保留并增加 AI 生成入口 |
| Credit | XP 演示值 | 本地按训练计算 20–120 | 后续接入每日 +5、视频 +15、服务端账本和幂等结算 |
| 周期进化 | 每次训练触发事件 | 尚未接入 React | 使用“当天/3天/5天/7天 + Credit”双门槛 |
| 视频动作核验 | 缺失 | 缺失 | 新增可选加成流程 |
| 登录注册 | 缺失 | 缺失 | 新增新手流程 |
| 历史记录 | 仅摘要 | 已实现训练历史 | 并入“我的”，增加 Credit 与星球版本 |

## 3. 代码与资产差异

| 项目 | 说明 | 决策 |
| --- | --- | --- |
| 大体积 PNG | 参考包 `src/imports/` 有多张 0.8–7 MB PNG | 不直接入库；继续使用已优化 WebP |
| 卡片背景 | 两边均有 L1–L5 WebP | 当前仓库版本体积 12–35 KB，保留 |
| 系统插画 | 两边均有黑洞与物质扫描 WebP | 保留当前语义化路径 |
| 3D 实现 | 参考包为 React/Three 组件，仓库为独立 JS 原型 | 在开发迭代中迁移到统一 React 数据模型，避免双实现长期并存 |
| 样式 | 参考包依赖 Figma AstraUI 和大量页面 CSS | 不整包覆盖；按手机端 token 与组件逐步迁移 |
